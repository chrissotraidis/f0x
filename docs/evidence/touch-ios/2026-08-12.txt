Live Simulator interaction (one F0X process, real UIKit touches synthesized
through the Simulator window at Point Accurate scale)
------------------------------------------------------------------
- The overlay renders with the hand-authored tablet layout: analog stick,
  D-pad group, ACCEL/BOOST/BRAKE, SLIDE L / SLIDE R, START, VIEW, LOOK, C-left,
  L, and the permanent ••• menu button at the upper-right safe area.
- Touch -> N64 pad-state chain verified through the app's debounced state log
  (the exact state input_bridge.c merges each frame):
    START = buttons=0x1000, L = 0x0020, ACCEL = 0x8000, BOOST = 0x4000,
    BRAKE = 0x0004, D-pad down = 0x0400.
    Analog stick: buttons=0x0000 stick=(...) active=1 with values that change
    with the drag and release to neutral on touch-up.
- START on the title advanced the game to SELECT MODE; a complete touch-driven
  GP flow reached a live race: SELECT MODE -> GP RACE -> STANDARD -> JACK CUP
  (MUTE CITY) -> BLUE FALCON -> machine settings -> race start, where holding
  ACCEL accelerated the Blue Falcon (0 -> 41 km/h) before a wall stall.
- The ••• button opened the full GdxMenu (Settings/Enhancements/Workshop/
  Online/Dev Tools; the log recorded "menu visible -> gameplay overlay hidden")
  and closed it ("menu closed -> overlay restored").
- Auto-hide with physical controller works: the Simulator exposes two MFi
  gamepads to SDL, and with gSettings.Touch.AutoHideWithController=1 the
  gameplay overlay is hidden (the log's controllerAutoHidden reason); setting
  the CVar to 0 restored the overlay for touch testing.
- Safe-area awareness: control frames follow window.safeAreaInsets; the tablet
  layout positions all controls inside the safe rect (verified via the attach
  log's exact frames).
